# Tracking plan

The browser events Signals accepts from the storefront tracker (the Lens beacon at `/t`), and the properties each may
carry. Ingest holds every event to this plan:

- **A property the plan doesn't list for that event is dropped.** So is a planned property of the wrong type.
- **Properties only the server sets are dropped** when a browser sends them, so a forged `is_bot`, revenue or event
  name can't reach a report.
- **An event named with the reserved `$` prefix that isn't planned is dropped.** Any other name is the merchant's own
  (a `data-lens-event` value, a toggle's label, an experiment goal from `trackGoal`) and is kept, held to the `custom`
  entry: any string, number or bool property, and nothing nested.
- **Each of these is counted** per shop and day, and shown under **Data health** on the Lens overview, so a tracker
  that drifts from the plan shows up instead of quietly losing data.
- **Bots are flagged on every event,** not only page views, and their clicks and scrolls stay out of the heatmaps.

Server-side events (carts, orders, email engagement, accounts) come from core and Signals themselves and aren't held to
this plan. Their shapes are fixed in code.

To change the plan, edit `TrackingPlan` in `apps/backend/signals/internal/analytics/plan.go` and run `skelet gen`.

| Event | What it means | Properties |
|---|---|---|
| `page_view` | A page was shown. Product pages describe the product they show. | `entity` string, `entity_image` string, `entity_name` string, `entity_price` string, `search_query` string, `sku` string, `utm_campaign` string, `utm_medium` string, `utm_source` string, `attr:<slug>` string |
| `product_filter` | A shopper narrowed a product list. | `filters` string, `attr:<slug>` string |
| `$search` | An on-site search and how many results it found. | `query` string, `results` number |
| `$experiment` | The variation of an experiment a shopper saw. | `experiment` string, `variation` string |
| `$js_error` | A script error on the page. | `line` number, `message` string, `sessionId` string, `source` string |
| `$rage_click` | Three or more clicks in one spot within a second. | `selector` string, `sessionId` string, `text` string, `x` number, `y` number |
| `$dead_click` | A click that changed nothing on the page. | `selector` string, `sessionId` string, `x` number, `y` number |
| `$web_vitals` | A Core Web Vitals measurement. | `metric` string, `sessionId` string, `value` number |
| `view_item` | A product was viewed. Older storefronts send it; the server's own events are the source of truth. | `sku` string |
| `begin_checkout` | Checkout was opened. Older storefronts send it. | none |
| `purchase` | An order was placed. Older storefronts send it; revenue only ever comes from the server's order events. | none |
| `custom` | Any other name is the merchant's own: a data-lens-event, a toggle opened or closed, a CMS block seen, an experiment goal. It may carry any string, number or bool property. | `action` string, `source` string, any other string, number or bool |

Set only by the server, and stripped when a browser sends them: `bot_category`, `bot_name`, `client`, `country`, `currency`, `device`, `ip`, `is_bot`, `machine`, `name`, `os`, `page_key`, `referrer`, `revenue_cents`, `title`, `total_cents`, `viewport`.
